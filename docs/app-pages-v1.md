# App 页面规划 v1（MVP 锁定：运动模块）
> **这一版定了三件事**：① MVP 只做运动模块，不再两线平均用力；② 全 App 的信息架构先定死，但分「MVP 期」与「全量期」两级；③ 先交付 **1 个可运行的模板页**——运动模块的「引导器」屏，它就是后面所有页面的样板。   

---

## 0\. 模块顺序的调整说明（为什么这次先做运动）

上一版规划里我建议的 P0 偏睡眠线（B 连续波：共振 \+ 睡前慢呼吸）。你选了**运动模块**优先，这个选择在工程上其实更优，理由有三条：

| 维度 | 睡眠线（原 P0） | **运动线（现 P0）** |
|------|---------------------|-------------------------|
| 技术风险 | **依赖锁屏后台音频**——整个方案里唯一的高风险假设 | 不依赖它，运动时屏幕本来就亮着，**绕开最大风险** |
| 差异化 | 强，但国内已有潮汐/Now冥想占位 | **最强**——踏频耦合呼吸（F 原型）是中文市场的空白，市面无产品 |
| 证据 | 强（Sleep Med Rev 2026，须 28-30 天） | 强且即时（耦合率 26.3%→69.9%；MSSE 2026 骑后恢复 p=0.001） |

**结论：先运动、后睡眠，但两者共享同一套引擎。** 关键洞察是——运动模块要的 A 原型（方盒/4-4-6）正是睡眠线也要用的，引擎一次做对，两线都能上。

## 1\. 信息架构总图（4 Tab \+ 1 全屏引导器）
```
┌─ 首页 ──── 今日推荐（1 张主卡，按时间+场景切换）
│            快捷开始（最近常练 3 个，一键进引导器）
│            [MVP 期：只放运动场景推荐]
│
├─ 练习 ──── 四组课程库：运动组 / 睡眠组 / 减压组 / 调息组
│            [MVP 期：只开运动组，其余三组显示「敬请期待」占位]
│            └─ 课程详情页（做法 + 证据卡 + 安全提示 + 开始）
│
├─ 记录 ──── 日历热力图 / 累计分钟 / 连续天数 / 技法分布
│            [MVP 期：只做本地记录 + 简化列表，不做图表]
│
├─ 我的 ──── 提醒设置 / 练习偏好 / 证据来源 / 免责声明
│
└─ ★ 全屏引导器（核心页，MVP 必做）
     相位动效 + 阶段提示 + 倒计时
     三通道：视觉 / 声音 / 触觉
     倍速（标准 / 慢 / 更慢）
     结束页（记录 + 分享卡片 + 顺手订提醒）
```

**MVP 期不做**：社交/排行榜、社区、AI 生成课程、iOS 虚拟支付、多语言、云同步。

## 3\. 运动模块的课程结构（4 课，覆盖 3 种原型）

| 课程 | 时机 | 时长 | 技法 | 原型 | 证据锚点 |
|------|------|------|------|------|------------|
| **骑前唤醒** | 出门前 / 上骑行台前 | 3-5 分钟 | 鳄鱼式呼吸 \+ 方盒 4-4-4-4 | **G \+ A** | 膈肌意识训练；警察模拟实战表现提升 |
| **骑行节奏呼吸** | 行进中 | 全程 | 吸 3 圈踏频 / 呼 2 圈踏频 | **F** | 声引导使呼吸-步频耦合率 26.3%→69.9% |
| **骑后恢复** | 到家拉伸时 | 5 分钟 | 4-4-6 简化版 | **A** | MSSE 2026：副交感再激活显著加快（HF-HRV p=0.001） |
| **关键时刻** | 出发前 / 爬坡前 | 2 分钟 | 方盒 4-4-4-4 | **A** | 箱式呼吸独有「注意力抑制错误减少」红利 |

**课程详情页的证据卡**是差异化重点：每节课直接标出证据等级与出处（研究者、年份、样本量、效应量），并诚实标注薄弱处（例如 4-7-8 在睡眠线要标「生理证据弱、主观口碑强，定为仪式型」）。

## 4\. 核心页拆解：引导器（模板页的结构）

**布局（上→下）**
1. 顶部：课程名 \+ 循环进度（3/6）
2. 中央：**相位轨道**（方盒=方形轨道 / 连续=圆环）\+ 中心呼吸球 \+ 阶段文字（吸气/屏息/呼气/保持）\+ 秒数倒计时
3. 底部：暂停 / 结束（弱化，避免误触）\+ 三通道开关 \+ 倍速
4. 结束页：本次时长、完成循环数、一句鼓励、保存分享卡、顺手订下一条提醒

**状态机（模板必须实现这个骨架）**
```
idle → prepare(3-2-1 预备) → running(相位序列循环)
      ↕ paused                    ↓ 循环结束/手动结束
      └────────────────────── finish(记录 + 分享)
```

**相位模型（数据驱动的关键，决定扩展性）**
```
phases: [{ name: "inhale", sec: 4 },
         { name: "hold",   sec: 4 },
         { name: "exhale", sec: 4 },
         { name: "hold2",  sec: 4 }]
cycles: 6
```

方盒 / 4-7-8 / 4-4-6 / 共振 / 生理性叹息，**全部是这一份配置的不同取值**——这就是「1 个时间轴引擎 \+ N 个渲染模板」的落地方式。新增技法 = 加一行配置。

**F 原型的踏频同步**：把 `sec` 从「秒」换成「踏频圈数」（吸 3 圈 / 呼 2 圈），由实时 BPM 换算成秒。**同一个状态机，只是时间基准换成外部信号。**

## 5\. 页面流转的黄金路径

**骑行日主路径**：首页 → 运动 Tab → 骑前唤醒详情 → 引导器（3-5 分钟）→ 结束页 → 顺手订「骑后恢复」提醒

**行进中路径**：运动 Tab → 骑行节奏呼吸 → 引导器（连接踏频 / 或手动节拍）→ 结束

设计原则：**从打开到开始练，不超过 2 步**；当天场景由首页主卡自动推荐，减少决策。

## 6\. 技术约束对页面设计的硬影响

| 约束 | 对设计的影响 |
|------|------------------|
| 小程序 **不支持内联 SVG** | 相位动效必须用 **canvas 2d \+ requestAnimationFrame**；模板页已按此实现 |
| 后台/锁屏音频有限制 | 睡眠场景的命门；**运动场景不依赖它**，这也是 MVP 先做运动的隐性收益 |
| 订阅消息是**一次性**订阅 | 不能做「每晚自动提醒」→ 设计成「练完顺手订下一条」 |
| iOS 部分机型无振动 | 触觉是**增强通道**而非依赖通道，视觉/声音必须永远可用 |
| 无 iOS 虚拟支付 | 自用版不做内购，纯工具 |
| 本地存储够用 | MVP 用 `wx.setStorageSync`，云开发推迟到 P2 |

## 7\. F 原型的三级降级设计（决定它能否进 MVP）

踏频同步是差异化核心，但它依赖 BLE。三级降级让它在任何条件下都能用：

| 级别 | 条件 | 体验 |
|------|------|------|
| L1 完整版 | 连上 BLE 踏频传感器（服务 0x1816） | 圆环转速与真实踏频同步，吸 3 圈 / 呼 2 圈 |
| L2 手动档 | 未连传感器 | 用户选 60 / 80 / 90 / 100 rpm，圆环按该节拍走 |
| L3 纯节拍 | 什么都不连 | 手机节拍音 \+ 视觉脉冲，用户自己贴节拍 |

**L2/L3 让 F 原型零依赖进 MVP**，BLE 到 P1 再补——这是把「高风险依赖」变成「可选增强」的标准做法。

## 8\. 待拍板
1. **MVP 是否就做这 6 个屏？** 我的建议是把「记录」压到最简（只做列表 \+ 连续天数），把工时全砸在引导器上。
2. **F 原型进 MVP 吗？** 我建议进，但只做 L2 手动档 \+ L3 节拍，BLE 放 P1。
3. **分享卡片要不要现在就做？** 它是「发朋友」这个验收标准的载体，但会多花 1-2 天。
4. **首页要不要做？** 如果 MVP 期只有运动组，首页可能退化成「运动 Tab」的镜像——也可以先不做首页，四个 Tab 砍成三个。
